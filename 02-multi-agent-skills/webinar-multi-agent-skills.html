Core Concept

What Are Skills?

The new unit of operational knowledge

Structured markdown — metadata, triggers, step-by-step instructions, and validation criteria
Portable — not locked to one agent or team. Anyone can discover and use them
Versionable — treat like code. Git-tracked. Semantic versions in the registry
Testable — includes expected tool sequences and example inputs/outputs for evaluation
SKILL.MD
--- name: k8s-healthcheck description: Diagnose K8s workload health --- ## Tools k8s_get_resources, k8s_describe_resource, k8s_get_events, k8s_get_pod_logs ## Procedure 1. Get target deployment/statefulset 2. List all pods owned by resource 3. For unhealthy: describe + logs 4. Check events for warnings 5. Produce structured report ## Diagnosis Rules Pending + no events = scheduling issue ImagePullBackOff = check image/registry CrashLoopBackOff = read prev logs, OOM?

02
Skill Structure

Anatomy of a Skill

A skill is a folder. SKILL.md is the only required file.

FILE STRUCTURE
k8s-healthcheck/ ├── SKILL.md # Required ├── scripts/ │ └── validate.sh # Optional ├── references/ │ └── k8s-patterns.md # Optional └── assets/ └── templates/ # Optional
File must be exactly SKILL.md — case-sensitive. No variations.

Progressive Disclosure

Three-level system to minimize token usage. 20 skills at Level 1 ≈ 1K tokens. All 20 fully loaded ≈ 30K tokens.

LEVEL 1 — YAML FRONTMATTER

Always loaded in the agent's system prompt. Just enough to know when to activate.

LEVEL 2 — SKILL.MD BODY

Loaded when the agent determines the skill is relevant. Full instructions and guidance.

LEVEL 3 — LINKED FILES

Additional files in scripts/, references/, assets/. Loaded on demand only.

The Relationship

MCP is the Kitchen. Skills are the Recipes.

MCP gives you tools, ingredients, and equipment. Skills teach you how to cook.

MCP (Connectivity) Skills (Knowledge)
Connects to your services Teaches how to use them effectively
Provides real-time data & tool access Captures workflows & best practices
What the agent can do How the agent should do it
Together, they enable complex tasks without users figuring out every step.

Writing Effective Descriptions

FORMULA
[What it does] + [When to use it] + [Key capabilities]

✅ GOOD

Diagnoses K8s workload health. Use when user asks to "check pods", "healthcheck", or "why is my deployment failing".

❌ BAD

Helps with Kubernetes.
Design Approach

Two Ways to Build Skills

Think of it like Home Depot. You either walk in with a problem, or you walk in to learn what a tool can do.

Problem-First

"I need to diagnose a failing deployment." The skill orchestrates the right MCP calls in the right order. Users describe outcomes — the skill handles the tools.

# User says: "Why is my deployment failing?" # Skill orchestrates: 1. k8s_get_resources 2. k8s_describe_resource 3. k8s_get_events 4. k8s_get_pod_logs → Structured diagnosis

Our k8s-healthcheck & incident-response skills use this pattern.

Tool-First

"I have Kubernetes MCP connected." The skill teaches optimal workflows and best practices for tools you already have access to. Users have access — the skill provides expertise.

# User has: k8s MCP server # Skill teaches: "Always dry-run before apply" "Check events before diving into logs" "Verify rollout status after deploy" "If OOMKilled, check limits first"

Our k8s-deploy skill uses this pattern — best practices for safe deploys.

Most skills lean one direction. Knowing which framing fits your use case helps you write better instructions.

TREE

Composable — reference skills across repos, teams, and organizations
Skills are just files. Git is the distribution mechanism.

Anthropic Best Practices

Five Proven Skill Patterns

From Anthropic's guide — patterns that work across use cases.

1. Sequential Workflow

Multi-step processes in a specific order. Explicit step ordering, dependencies between steps, validation at each stage.

e.g. Our k8s-healthcheck: get_resources → describe → events → logs

2. Multi-MCP Coordination

Workflows spanning multiple services. Clear phase separation, data passing between MCPs, validation before moving to next phase.

e.g. Diagnose in K8s → create ticket in Jira → notify in Slack

3. Iterative Refinement

Output quality improves with iteration. Generate draft, run quality checks, fix issues, re-validate. Repeat until threshold met.

e.g. Generate report → validate → fix → re-validate

4. Context-Aware Tool Selection

Same outcome, different tools depending on context. Clear decision criteria, fallback options, transparency about choices.

e.g. Pod pending? Check node resources vs. check scheduling

5. Domain-Specific Intelligence

Your skill adds specialized knowledge beyond tool access. Domain expertise embedded in logic, compliance before action, comprehensive documentation. This is the pattern our K8s skills use — encoding 8 years of SRE knowledge into executable procedures.

Watch Out

Common Skill Mistakes

These will save you hours of debugging.

Skill Never Triggers

Description is too vague. "Helps with Kubernetes" won't match anything.

❌ Bad

description: Helps with projects.

✅ Fix

description: Diagnoses K8s workload health. Use when user asks "check pods" or "why is my deploy failing".

Skill Triggers Too Often

Description is too broad. Fires on every Kubernetes question.

# Add negative triggers: description: Advanced data analysis for CSV files. Use for statistical modeling. Do NOT use for simple data exploration (use data-viz skill instead).

Instructions Not Followed

Instructions too verbose or buried. Agent skips critical steps.

❌ Vague

Validate the data before proceeding.

✅ Specific

CRITICAL: Before apply, verify: - dry-run passes - resource limits set - readiness probe defined

Slow or Degraded Responses

SKILL.md too large or too many skills enabled.

Keep SKILL.md under 5,000 words
Move detailed docs to references/
If 20+ skills enabled, use skill "packs"
Debug tip: Ask the agent "When would you use the [skill name] skill?" — it will quote the description back. Adjust based on what's missing.
