The Problem

Building one agent is easy.
Orchestrating many is not.

  • Skills are trapped inside individual agent configs
  • No discovery — agents can't find each other's capabilities
  • No validation — "works when I'm watching" ≠ works autonomously
  • No governance — who approved this skill for production?

Skills vs. MCP vs. Prompts

Skills

Procedural expertise — how to do something. Persists across conversations. Discovered dynamically.

MCP

External connectivity — access to tools and data. Live APIs, databases, dev environments.

Prompts

Moment-to-moment instructions — one-off requests. No persistence, no reuse.

The insight: MCP gives agents access. Skills teach agents expertise. You need both — but Skills are where the compounding happens.

Foundation

What is a Skill?

A reusable, composable unit of capability that an agent loads at runtime.

"Good enough for my use" and "good enough for agents" are categorically different standards.

5 things every skill body needs:

  • Clear trigger conditions (when to activate)
  • Structured instructions (how to execute)
  • Example inputs & outputs
  • Error handling & fallbacks
  • Validation criteria (how to verify success)
# SKILL.md — anatomy of a skill ## Description ← where most skills fail Deploy Kubernetes manifests with dry-run validation and rollback support ## Triggers - "deploy to k8s", "apply manifest" - file type: .yaml with kind: Deployment ## Instructions 1. Validate manifest schema 2. Run dry-run against target cluster 3. Apply with --record for rollback 4. Verify readiness probe passes ## Error Handling - Schema invalid → return error + fix - Dry-run fails → diff against running - Timeout → check events + rollback ## Validation - Pod status = Running - Readiness check passes within 60s

Registry

agentregistry — Discover, Publish & Govern

The Problem It Solves

MCP servers, skills, and agents are scattered across npm, PyPI, Docker Hub, and random repos. No central discovery. No quality signals. No governance.

Core Capabilities

  • Discover — Semantic search, quality scores, enriched metadata
  • Publish — Register via REST API or Web UI
  • Govern — Curation workflows, approval gates, security controls
  • Deploy — Auto-configure Claude Desktop, Cursor, VS Code

Gateway Integration

Routes through agentgateway — an AI-native reverse proxy for secure, managed MCP traffic.

# Register a skill via REST API $ curl -X POST http://localhost:12121/v0/skills \ -H "Content-Type: application/json" \ -d '{ "name": "k8s-deploy", "version": "1.0.0", "description": "Deploy K8s manifests with dry-run validation and rollback", "category": "kubernetes" }' # Search for skills $ curl -s "http://localhost:12121/v0/skills?search=kubernetes" # Get a specific skill version $ curl -s http://localhost:12121/v0/skills/k8s-deploy/versions/1.0.0

Evaluation

agentevals — Score from Traces, Not Re-runs

The Core Insight

Record once. Evaluate infinitely.
No re-runs. No wasted tokens. No guesswork.

How It Works

1 Instrument agent with OpenTelemetry
2 Define golden eval sets (expected behavior)
3 Run evaluations → per-metric scores

Framework Agnostic

Works with any OTel-instrumented framework: LangChain, Strands, Google ADK, OpenAI Agents SDK — and kagent.

# Golden eval set — expected behavior name: "deploy-skill-validation" expected_trajectory: - tool: "kubectl-dry-run" args_contain: "--dry-run=server" - tool: "kubectl-apply" args_contain: "--record" - tool: "kubectl-rollout-status" expected_output: contains: "deployment successful" timeout: 120s # Run evaluation from CLI $ agentevals run \ --trace-file traces/deploy-run-042.json \ --eval-set evals/deploy-skill.yaml METRIC SCORE STATUS tool_trajectory 0.95 ✓ PASS response_quality 0.88 ✓ PASS error_handling 0.72 ⚠ WARN ──────────────────────────────── OVERALL 0.85 PASS

Patterns

Multi-Agent Collaboration Patterns

Skill Sharing

Agents discover and pull skills from agentregistry at runtime. No hard-coded dependencies.

# Agent A needs deploy capability skill = registry.search( "kubernetes deploy" ) agent.load_skill(skill)

Capability Routing

Agentgateway routes requests to the agent with the right skills. MCP-native traffic management.

# Gateway routes by capability route: match: tool.category == "deploy" target: deploy-agent fallback: general-agent

Safe Execution

Every skill invocation is OTel-traced. Evaluate any run against golden sets. Catch regressions in CI.

# CI pipeline step - name: Validate skills run: agentevals run \ --eval-set evals/ \ --trace-dir traces/

Takeaways

What to remember

1

Skills are the primitive

Invest in making skills robust, well-described, and agent-ready. The description field is where most skills fail.

2

The registry is the multiplier

Turn individual skills into shared organizational capability. Discovery + governance = trust at scale.

3

Evaluation closes the loop

Without it, you're deploying skills that silently fail. OTel traces + golden eval sets = confidence.

The conventional approach — building a skill that works when you're watching — quietly fails the moment the human leaves the loop.
